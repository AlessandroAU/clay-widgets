## Requirements

The implementation toolchain is GCC or Clang in C++20 mode. The public API has C
linkage, but the implementation uses the pinned Clay build's C++ macros and
compound-literal extensions; MSVC and strict C builds are not verified.

The tested Clay revision is `e6cc36941ab2af5d81107617039d6f527a1c660b` (the
`subprojects/clay` gitlink). Use that revision with the amalgam too. Clay's
Begin/End helpers are isolated in `core.h`, so arbitrary upstream Clay versions
are not interchangeable.

Include `clay.h` and then `clay-widgets/widgets.h` - the umbrella header that
pulls in every widget header in dependency order. Define `CLAY_WIDGETS_IMPLEMENTATION`
(alongside Clay's own implementation macro) in exactly one translation unit. The
single-file amalgam generated by `make amalgam` is included the same way.

All UI calls run on the same thread as the current Clay context.

## Setup and the frame loop

```cpp
ClayWidgets_Context ui = {};
ClayWidgets_Init(&ui, ClayWidgets_DefaultTheme());
ClayWidgets_SetMeasureTextFunction(&ui, MeasureText, &fontCache);
ClayWidgets_SetClipboardFunctions(&ui, GetClipboard, SetClipboard, nullptr);

// per frame:
ClayWidgets_BeginFrame(&ui, input, layoutSize, /*enableDragScroll=*/true);
    // ... declare Clay elements and widgets ...
    ClayWidgets_ToastLayer(&ui);        // last, if you use toasts
Clay_RenderCommandArray cmds = ClayWidgets_EndFrame(&ui);
applyCursor(ClayWidgets_GetCursor(&ui));
render(cmds);
```

`ClayWidgets_BeginFrame` opens Clay's layout pass itself and `ClayWidgets_EndFrame`
closes it and returns the render commands - do not call `Clay_BeginLayout` /
`Clay_EndLayout` around them.

```c
void ClayWidgets_Init(ClayWidgets_Context *ctx, ClayWidgets_Theme theme);
void ClayWidgets_SetMeasureTextFunction(ClayWidgets_Context *ctx, ClayWidgets_MeasureTextFunction fn, void *userData);
void ClayWidgets_SetClipboardFunctions(ClayWidgets_Context *ctx, ClayWidgets_GetClipboardTextFunction get,
                                       ClayWidgets_SetClipboardTextFunction set, void *userData);
void ClayWidgets_SetClipboardWriteFunction(ClayWidgets_Context *ctx, ClayWidgets_TrySetClipboardTextFunction fn);
void ClayWidgets_SetErrorHandler(ClayWidgets_Context *ctx, ClayWidgets_ErrorHandlerFunction fn, void *userData);
void ClayWidgets_BeginFrame(ClayWidgets_Context *ctx, ClayWidgets_Input input,
                            Clay_Dimensions layoutSize, bool enableDragScroll);
Clay_RenderCommandArray ClayWidgets_EndFrame(ClayWidgets_Context *ctx);
ClayWidgets_Cursor ClayWidgets_GetCursor(const ClayWidgets_Context *ctx);
void *ClayWidgets_GetState(ClayWidgets_Context *ctx, uint32_t id, int32_t size);
```

`ClayWidgets_GetCursor` returns the hovered widget's cursor hint
(`DEFAULT`, `POINTER`, `TEXT`, `RESIZE_X`, `RESIZE_Y`, `RESIZE_XY`); read it
after `EndFrame` and apply it with the platform cursor API. It resets to
`DEFAULT` each `BeginFrame`.

Without clipboard functions the copy/cut/paste keys are ignored. A void `set`
is assumed to succeed; an adapter that can detect failures installs
`ClayWidgets_SetClipboardWriteFunction` as well, whose bool setter takes
precedence and shares the clipboard user data.

`ClayWidgets_GetState` is the retained-state building block for custom widgets:
`size` bytes of POD storage keyed by element id, zeroed on first use and kept
while the id keeps asking. Slots are recycled least-recently-used; it returns
NULL when the request is invalid or the pool is exhausted, so callers must
degrade rather than crash. Treat zeroed state as "the widget just appeared".

Exceeding a compile-time cap at runtime is reported once per category per frame
through the error handler; with none installed, `CLAY_WIDGETS_ASSERT` prints and
aborts in debug builds and does nothing under `NDEBUG`.

## Conventions

- **Return values.** Widgets that edit a value take it as a pointer and return
  true on the frame they changed it (checkbox, toggle, radio, tab, segmented,
  slider, stepper, combo, listbox, text input, text area). Activation widgets
  (button, menu item) return true when activated. Begin/End pairs return whether
  their body should be emitted. Display-only widgets return void.
- **Ids** must be stable across frames; interaction state is keyed by them.
- **Strings are borrowed.** Text passed in, and text returned from callbacks,
  must stay valid until rendering finishes - Clay retains text by pointer.
  Buffer capacities always include the NUL terminator.
- **One frame of lag.** Hit testing, layout queries and semantic bounds use the
  previous frame's geometry, so a newly opened overlay settles on the next frame.
- **Disabled scopes** nest:

  ```cpp
  if (ClayWidgets_BeginDisabled(&ui)) { /* ... */ ClayWidgets_EndDisabled(&ui); }
  ```

  Everything inside is inert and muted, including widgets that have no
  individual `disabled` option. Pair every successful Begin with End.

## Input

`ClayWidgets_BeginFrame` takes a `ClayWidgets_Input` filled by the platform layer:

| Group | Fields |
| --- | --- |
| Pointer | `mouseX`, `mouseY`, `pointerDown`, `pointerPressed`, `pointerReleased`, `pointerRightPressed` |
| Wheel / timing | `scrollX`, `scrollY`, `deltaTime` |
| Text | `textUtf8`, `textUtf8Length` (UTF-8 bytes typed this frame) |
| Editing keys | `keyBackspace`, `keyDelete`, `keyHome`, `keyEnd`, `keyLeft`, `keyRight`, `keyUp`, `keyDown`, `keyEnter`, `keyEscape`, `keySpace` |
| Commands | `keyTab`, `keySelectAll`, `keyCopy`, `keyCut`, `keyPaste`, `keyUndo`, `keyRedo` |
| Modifiers | `shiftDown`, `controlDown` (Command on macOS) |
| IME | `compositionUtf8`, `compositionLength`, `compositionCursor` |

Editing and navigation keys should honor OS key repeat so held keys keep acting.
`keyTab` with `shiftDown` traverses focus backwards; `controlDown` drives word
navigation and additive selection.

## Theming

`ClayWidgets_Theme` is a plain struct on the context - assign `ui.theme` at any
time, including per frame. It carries colors (`textColor`, `textMutedColor`,
`surfaceColor`, `surfaceAltColor`, `accentColor`, `accentMutedColor`,
`borderColor`, `hoverColor`, `pressedColor`, `focusRingColor`), the shared status
palette (`successColor`, `warningColor`, `dangerColor`) used by badges, toasts
and danger buttons alike, `onAccentColor` for glyphs drawn on those fills,
`scrimColor`, `disabledMix` (how far disabled fills flatten toward the surface),
`fieldColor` (the background of anything typed or picked into - text fields, list
boxes, table bodies), `selectionColor`/`onSelectionColor` (the highlight bar
behind a hovered menu item, dropdown item or list row, and its text), the
`radiusSm`/`radiusMd` corner radii, font ids (`fontBody`, `fontHeading`,
`fontMono`), font sizes (`fontSizeBody`, `fontSizeHeading`, `fontSizeSmall`) and
a `spacing` scale (`xs`, `sm`, `md`, `lg`).

### 3D edges and drop shadows

`edgeStyle` picks how widgets draw their edges. `CLAY_WIDGETS_EDGE_STYLE_FLAT`
(the default, and what every preset but Win95 uses) draws a 1px line in
`borderColor`. `CLAY_WIDGETS_EDGE_STYLE_BEVEL` draws the classic Windows 3.x/9x
two-tone edges instead, built from `edgeLightColor` / `edgeHighlightColor` on the
top-left and `edgeShadowColor` / `edgeDarkColor` on the bottom-right, and lets
floating chrome cast a hard drop shadow (`shadowColor`, `shadowOffset`; offset 0
disables it).

A Clay element carries one border color and a classic edge needs four, so beveled
edges are not Clay borders: a widget tags its element and `ClayWidgets_EndFrame`
paints the bands straight into the render command array, around the element's own
background rectangle. That costs no layout elements and needs no renderer
support - a renderer only ever sees ordinary rectangles - but it does need room
in Clay's render command array, so a beveled UI wants a little extra headroom in
`Clay_Initialize`'s element count.

Custom widgets can ask for the same treatment:

```c
// No-ops unless the theme is beveled (SetShadow: unless shadowOffset > 0), so
// both are safe to call unconditionally.
void ClayWidgets_SetEdge(ClayWidgets_Context *ctx, Clay_ElementId id, ClayWidgets_Edge edge);
void ClayWidgets_SetShadow(ClayWidgets_Context *ctx, Clay_ElementId id);
```

`ClayWidgets_Edge` is `NONE`, `RAISED` and `SUNKEN` (the 2px control edges),
`RAISED_THIN` / `SUNKEN_THIN` (1px, for strips and etched grooves) and `FRAME`
(a 1px hard outline). The element must paint a background - the edge is anchored
to its background rectangle - and `CLAY_WIDGETS_MAX_DECORATIONS` (512) caps how
many elements can be tagged in one frame.

```c
ClayWidgets_Theme ClayWidgets_DefaultTheme(void);
ClayWidgets_Theme ClayWidgets_ThemeSlate(void);
ClayWidgets_Theme ClayWidgets_ThemeSand(void);
ClayWidgets_Theme ClayWidgets_ThemeForest(void);
ClayWidgets_Theme ClayWidgets_ThemeWin95(void);
ClayWidgets_Theme ClayWidgets_ThemeFromPreset(ClayWidgets_ThemePreset preset); // SLATE=1, SAND=2, FOREST=3, WIN95=4
```

`ctx->animationsEnabled` (default true) globally turns transitions off so they
snap - use it for reduce-motion preferences and deterministic screenshots.

## Text and display

```c
void ClayWidgets_Label(ClayWidgets_Context *ctx, Clay_String text);
void ClayWidgets_Heading(ClayWidgets_Context *ctx, Clay_String text);
void ClayWidgets_Separator(ClayWidgets_Context *ctx);
void ClayWidgets_Badge(ClayWidgets_Context *ctx, Clay_String text, ClayWidgets_BadgeVariant variant);
void ClayWidgets_BadgeColor(ClayWidgets_Context *ctx, Clay_String text, Clay_Color background, Clay_Color textColor);
void ClayWidgets_ProgressBar(ClayWidgets_Context *ctx, Clay_ElementId id, float progress01, Clay_String label);
void ClayWidgets_Image(ClayWidgets_Context *ctx, Clay_ElementId id, void *imageData, float width, float height);
void ClayWidgets_ImageEx(ClayWidgets_Context *ctx, Clay_ElementId id, void *imageData, float width, float height, Clay_Color tint);
void ClayWidgets_Icon(ClayWidgets_Context *ctx, Clay_ElementId id, void *imageData, float size, Clay_Color tint);
```

Badge variants are `NEUTRAL`, `ACCENT`, `SUCCESS`, `WARNING`, `DANGER`.

`imageData` is an opaque handle passed straight through to the renderer's IMAGE
command (a `Texture2D*` in the raylib backend); the widget layer never
dereferences it. `Icon` draws it square and tinted, so one white glyph texture
recolors per theme. The tint travels in the element's `userData` as a packed
`0xRRGGBBAA` (0 = untinted) rather than `backgroundColor`, because this Clay
build emits an extra rectangle for any non-zero background alpha. Use
`ClayWidgets_PackTint` / `ClayWidgets_UnpackTint` so widgets and renderer agree;
renderers that ignore `userData` simply draw untinted.

```c
bool ClayWidgets_Button(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String text);

bool ClayWidgets_Checkbox(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String text, bool *value);
bool ClayWidgets_CheckboxEx(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String text, bool *value, bool disabled);
bool ClayWidgets_Toggle(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String text, bool *value);
bool ClayWidgets_ToggleEx(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String text, bool *value, bool disabled);
bool ClayWidgets_Radio(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String text, int32_t optionValue, int32_t *selectedValue);
bool ClayWidgets_Tab(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String text, int32_t optionValue, int32_t *selectedValue);
bool ClayWidgets_TabEx(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String text, int32_t optionValue, int32_t *selectedValue, ClayWidgets_TabStyle style);
bool ClayWidgets_Segmented(ClayWidgets_Context *ctx, Clay_ElementId id, const Clay_String *segments, int32_t segmentCount, int32_t *selectedIndex);
bool ClayWidgets_Slider(ClayWidgets_Context *ctx, Clay_ElementId id, float *value, ClayWidgets_SliderOptions options);
bool ClayWidgets_Stepper(ClayWidgets_Context *ctx, Clay_ElementId id, int32_t *value, ClayWidgets_StepperOptions options);
```

`ClayWidgets_ButtonOptions` carries `variant` (`DEFAULT`, `PRIMARY`, `DANGER`),
`disabled`, and an optional `sizing` override - the zero value is
`CLAY_SIZING_FIT(0, 0)`, i.e. wrap to the label.

`ClayWidgets_SliderOptions` is `{minValue, maxValue, step, showValue,
valueDecimals, disabled}`; `valueDecimals <= 0` derives the precision from the
step and range. A focused slider steps with Left/Right (by `step`, or 1% of the
range) and jumps with Home/End. `ClayWidgets_StepperOptions` is
`{minValue, maxValue, step, disabled}`; a focused stepper increments with
Up/Right and decrements with Down/Left.

Tab styles are `PILL` (standalone navigation pill) and `ATTACHED` (top-rounded
with an accent underline, meant to sit in the header row of a framed tab plane).
Radios, tabs and segmented cells all behave as one-of-N over a caller-owned
selection; a focused segmented control moves with Left/Right.

## Editors

```c
bool ClayWidgets_TextInput(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String label,
                           char *buffer, int32_t capacity, ClayWidgets_TextInputOptions options);
bool ClayWidgets_TextArea(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String label,
                          char *buffer, int32_t capacity, ClayWidgets_TextAreaOptions options);
```

Both edit a caller-owned NUL-terminated UTF-8 buffer and return true when they
modified it. They share the focused-editing state (caret, selection, blink), so
at most one editor is focused at a time.

`ClayWidgets_TextInputOptions`: `placeholder`, `clearOnEnter`, `disabled`,
`readOnly`, `history`, `validate`, `validationUserData`, `result`.
`ClayWidgets_TextAreaOptions` adds `height` (0 = about five lines) and `noWrap`.

- `readOnly` keeps focus, navigation, selection and copy working while
  suppressing mutation. `disabled` also prevents focus and selection; the text
  is still shown.
- `history` is an optional caller-owned, zero-initialized
  `ClayWidgets_TextHistory` - one persistent instance per editor. It holds up to
  `CLAY_WIDGETS_HISTORY_DEPTH` (16) snapshots of `CLAY_WIDGETS_HISTORY_BYTES`
  (8,192, terminator included), so an instance is about 128 KiB: put it in
  application or static storage, never a per-frame local. Changing the buffer
  externally resets history; oversized text stays editable but sets
  `historyUnavailable`. A new edit discards the redo stack.
- `validate(text, length, userData)` accepts or rejects the proposed complete
  buffer. Rejection restores the text and selection. Rollback uses a temporary
  allocation, and allocation failure rejects the edit. The callback is
  synchronous.
- `result` is an optional `ClayWidgets_EditResult*`, overwritten on each call:
  `changed`, `submitted`, `cancelled`, `rejected`, `historyUnavailable`,
  `clipboardFailed`. The return value means the same thing as `changed`.

```cpp
static ClayWidgets_TextHistory history{};
ClayWidgets_EditResult result{};
ClayWidgets_TextInputOptions options{};
options.history = &history;
options.result = &result;
ClayWidgets_TextInput(&ui, CLAY_ID("Name"), CLAY_STRING("Name"),
                      name, sizeof(name), options);
if (result.submitted && !result.rejected) save(name);
```

Enter submits a single-line input; in a text area Enter inserts a newline and
Ctrl+Enter submits. Escape blurs and reports `cancelled` - it does not revert
the edits. Ctrl+Left/Right and Ctrl+Backspace/Delete work on words, and a text
area's Ctrl+Home/End reach the document boundaries. Word navigation treats
non-ASCII codepoints as word characters. In the text area, hard lines soft-wrap
at word boundaries unless `noWrap` is set, Up/Down move by visual row while
remembering the caret's preferred column, and paste normalizes CRLF and lone CR
to LF. Scrolling follows the caret, with a scrollbar emitted on overflow.

Cut only deletes after the copy fully succeeds. Large selections use a temporary
allocation rather than being truncated.

## Lists and tables

```c
bool ClayWidgets_Combo(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String label,
                       const Clay_String *items, int32_t itemCount, int32_t *selectedIndex);
bool ClayWidgets_ListBox(ClayWidgets_Context *ctx, Clay_ElementId id,
                         const Clay_String *items, int32_t itemCount, int32_t *selectedIndex);
bool ClayWidgets_SelectRow(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_Color swatch, Clay_String text, bool selected);
bool ClayWidgets_SelectRowEx(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_Color swatch, Clay_String text, Clay_String trailing, bool selected);
bool ClayWidgets_TreeNode(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String label, int32_t depth, bool *expanded);
bool ClayWidgets_TreeLeaf(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String label, int32_t depth);
```

The combo dropdown caps its height at about 40% of the layout and scrolls,
opens upward when there is no room below the trigger, and keeps the keyboard
highlight in view. `ListBox` renders every row and grows to fit - wrap it in a
scroll panel for a fixed height, or use `VirtualList` for large data. Use -1 for
"nothing selected". `SelectRow` is the standalone row for caller-owned loops: an
optional leading swatch (zero alpha omits it), a label and an optional dim
trailing string (zero length omits it). Tree rows are drawn one at a time by a
caller-owned recursion; declare a node's children only when `TreeNode` returns
true, passing `depth + 1`.

### Basic table

```c
typedef struct ClayWidgets_TableColumn { Clay_String title; Clay_SizingAxis width; } ClayWidgets_TableColumn;

bool ClayWidgets_BeginTable(ClayWidgets_Context *ctx, Clay_ElementId id, const ClayWidgets_TableColumn *columns, int32_t columnCount);
bool ClayWidgets_TableRow(ClayWidgets_Context *ctx, Clay_ElementId rowId, const Clay_String *cells, int32_t cellCount, int32_t rowIndex, bool selected);
void ClayWidgets_EndTable(ClayWidgets_Context *ctx, Clay_ElementId id);
```

Rows are zebra-striped, hover-highlighted and selectable (`TableRow` returns
true on click). Emit rows and call `EndTable` only when `BeginTable` returns
true. Up to 12 columns. Nested basic tables restore the enclosing column state.

### Virtual list, searchable combo, data table

```c
typedef Clay_String (*ClayWidgets_ItemTextFunction)(int32_t index, void *userData);
typedef Clay_String (*ClayWidgets_TableCellFunction)(int32_t row, int32_t column, void *userData);
typedef int (*ClayWidgets_TableCompareFunction)(int32_t rowA, int32_t rowB, int32_t column, void *userData);

bool ClayWidgets_VirtualList(ClayWidgets_Context *ctx, Clay_ElementId id, int32_t count,
    ClayWidgets_ItemTextFunction text, void *userData, int32_t *selected,
    ClayWidgets_VirtualListOptions options);   // { height, rowHeight, disabled }

bool ClayWidgets_SearchableCombo(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String label,
    const Clay_String *items, int32_t count, int32_t *selected, char *query, int32_t queryCapacity);

bool ClayWidgets_DataTable(ClayWidgets_Context *ctx, Clay_ElementId id,
    const ClayWidgets_TableColumn *columns, int32_t columnCount, int32_t rowCount,
    ClayWidgets_TableCellFunction cell, ClayWidgets_TableCompareFunction compare, void *userData,
    int32_t *order, bool *selection, ClayWidgets_TableState *state,
    ClayWidgets_TableOptions options);         // { height, rowHeight, minColumnWidth, disabled }
```

Callbacks return borrowed strings that stay valid through rendering.

`VirtualList` emits only the visible rows plus overscan, so normal rendering
cost follows the viewport, not the item count. Type-ahead searches labels and
can visit every item. Empty lists are fine.

`SearchableCombo` pairs an always-visible filter field with a dropdown. The
query buffer is caller-owned and persistent; filtering is substring matching
with ASCII case folding, and `*selected` always indexes the original array.
Filtering uses temporary descriptor/index arrays while label bytes stay
caller-owned. It suits moderate option counts - reach for `VirtualList` on very
large datasets.

`DataTable` drives a sortable, resizable, virtualized, multi-select grid.
`order` is a caller-owned permutation of `[0, rowCount)` and `selection` is
indexed by original record, so sorting preserves selection; both arrays have
`rowCount` entries. Initialize `order[i] = i`, clear `selection`, and
zero-initialize `ClayWidgets_TableState`. Callbacks must not mutate `order`
during layout.

- Clicking a header sorts ascending, then toggles direction. The sort is
  in-place and O(n log n), with the original row index breaking ties.
- Header dividers drag to resize. Widths live in `state.widths` (zero
  initializes from the column sizing). Grow columns share the remaining viewport
  width until manually resized; explicit widths stay fixed.
- The header sits outside the vertically scrolling, virtualized body.
- Click selects one row, Ctrl-click toggles, Shift-click selects an anchored
  range, Ctrl+A selects all, and arrow/Home/End navigation reveals the row.
- `sortChanged`, `selectionChanged` and `widthChanged` on the state reset on
  every call.
- Up to 12 columns. The application owns insertion and deletion, must keep the
  arrays a valid permutation/selection as records change, and re-applies sorting
  after data changes if it wants it.

## Containers and panels

```c
void ClayWidgets_BeginCard(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String title);
void ClayWidgets_BeginCardEx(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String title, Clay_SizingAxis width, Clay_SizingAxis height);
void ClayWidgets_EndCard(ClayWidgets_Context *ctx, Clay_ElementId id);
bool ClayWidgets_BeginCollapsible(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_String title, bool *open);
void ClayWidgets_EndCollapsible(ClayWidgets_Context *ctx, Clay_ElementId id);
Clay_ElementId ClayWidgets_BeginScrollPanel(ClayWidgets_Context *ctx, Clay_ElementId id, ClayWidgets_ScrollPanelOptions options);
void ClayWidgets_EndScrollPanel(ClayWidgets_Context *ctx, Clay_ElementId id);
void ClayWidgets_ScrollBar(ClayWidgets_Context *ctx, Clay_ElementId scrollContainerId);
```

A card is a bordered, padded surface; an empty title gives an untitled panel
with no header row or separator. `BeginCard` grows to its parent's width and
fits its content's height. A collapsible returns true while open - declare the
body and call `End` only then; a column of them forms an accordion.

`ClayWidgets_ScrollPanelOptions` is `{width, height, fadeMargin, padding,
childGap}`, where zeros take the theme defaults. The panel insets its content by
a vertical fade margin and a right-hand gutter so nothing renders under the
scrollbar, which it emits automatically. Scroll panels are not designed to nest.

```c
typedef struct ClayWidgets_SplitOptions { Clay_Sizing sizing; bool vertical; float minFirst, minSecond; } ClayWidgets_SplitOptions;
typedef struct ClayWidgets_ResizableOptions { float minWidth, minHeight, maxWidth, maxHeight; } ClayWidgets_ResizableOptions;

bool ClayWidgets_BeginSplit(ClayWidgets_Context *ctx, Clay_ElementId id, float *ratio, ClayWidgets_SplitOptions options);
void ClayWidgets_NextSplit(ClayWidgets_Context *ctx, Clay_ElementId id, bool vertical);
void ClayWidgets_EndSplit(ClayWidgets_Context *ctx);
bool ClayWidgets_BeginResizablePanel(ClayWidgets_Context *ctx, Clay_ElementId id, Clay_Dimensions *size, ClayWidgets_ResizableOptions options);
void ClayWidgets_EndResizablePanel(ClayWidgets_Context *ctx);
```

```cpp
ClayWidgets_SplitOptions split{};
split.sizing = {CLAY_SIZING_GROW(0), CLAY_SIZING_FIXED(240)};
split.minFirst = split.minSecond = 60;
if (ClayWidgets_BeginSplit(&ui, CLAY_ID("Panes"), &ratio, split)) {
    drawFirstPane();
    ClayWidgets_NextSplit(&ui, CLAY_ID("Panes"), split.vertical);
    drawSecondPane();
    ClayWidgets_EndSplit(&ui);
}
```

`ratio` is the caller-owned fraction of the container taken by the first pane.
The divider accepts drag, arrows and Home/End. A vertical split stacks the
panes. Give the split a definite size along its split axis; minimum sizes are
best-effort when their sum exceeds the space available. `BeginResizablePanel`
takes caller-owned dimensions with min/max constraints and resizes from its
corner handle by pointer or arrow keys. These are layout panels - not native
movable windows, and not a docking system.

```c
void ClayWidgets_ToastLayer(ClayWidgets_Context *ctx);
bool ClayWidgets_BeginDisabled(ClayWidgets_Context *ctx);
void ClayWidgets_EndDisabled(ClayWidgets_Context *ctx);
```

`BeginModal` opens a fixed, centered dialog; everything between Begin and End is
the body, and Begin returns false (opening no elements) when the dialog is
closed. `ClayWidgets_ModalOptions` is `{draggable, width}` - width 0 means 440px,
clamped to the viewport:

```cpp
ClayWidgets_BeginModalEx(&ui, CLAY_ID("Props"), CLAY_STRING("Properties"), &open, {true, 440});
```

Dragging starts on the title bar, excluding its close button. The position is
kept while open, constrained to the viewport when the dialog fits, and reset to
center on reopening. Drag state comes from the widget state pool; an exhausted
pool leaves the dialog centered. Both forms close on Escape, on a scrim click,
or via the X.

Modals trap keyboard focus: widgets outside leave the Tab order and give up
focus. Initial focus goes to the close button - call `ClayWidgets_RequestFocus`
with a body control's id to choose another. Closing restores the opener's focus.
Prefer opening a modal from a consumed widget action.

Modal, menu and combo layers are positioned relative to their enclosing overlay,
so keep Begin/End pairs balanced. Modal and overlay nesting are bounded at 16; a
Begin that cannot open returns false.

Only one menu is open at a time; clicking a title toggles it and, once any menu
is open, hovering another title switches to it. A menu closes when an item is
chosen, on a press outside, or on Escape. Context menus reuse `MenuItem` and
`MenuSeparator` but float at a stored cursor position.

Tooltips attach to an already-declared anchor by id, so emit them after the
anchor element closes while its parent is still open. They appear after the
pointer rests for `CLAY_WIDGETS_TOOLTIP_DELAY` (0.5s) and pass pointer events
through.

`ShowToast` appends to a queue of `CLAY_WIDGETS_MAX_TOASTS` (4), evicting the
oldest when full; `ToastLayer`, called once per frame near the end, counts the
timers down and draws the stack above everything else.

Keyboard behavior across overlays: Enter and Space activate controls; menus
support Up/Down, Home/End, Left/Right between menu-bar titles, Enter/Space to
choose and Escape to close; lists support Home/End and timed prefix search
(ASCII case folding, exact UTF-8 otherwise). Tab-focused controls and
keyboard-selected list items are revealed inside their enclosing scroll panel.

## Scrolling

Mouse-wheel scrolling eases to a stop, retaining Clay's total wheel distance.
`ui.scrollMomentumTime` sets the decay in seconds (default `0.10`); zero scrolls
immediately, and `ui.animationsEnabled = false` also disables wheel momentum.
Applications that already receive native trackpad inertia should turn this off
rather than apply it twice.

Momentum stays with its original scroll container when the pointer moves.
Changing direction responds immediately, and clicking, keyboard navigation,
opening or closing a modal, or setting a scroll position programmatically
cancels pending motion. Nested widget clips forward vertical wheel input to the
enclosing scroll area. Scrollbar dragging is always direct. Clay's own
drag-scroll momentum is separate, controlled by `enableDragScroll` in
`BeginFrame`.

## Accessibility and IME adapters

```c
void ClayWidgets_SetSemanticFunction(ClayWidgets_Context *ctx, ClayWidgets_SemanticFunction fn, void *userData);
void ClayWidgets_SetImeFunction(ClayWidgets_Context *ctx, ClayWidgets_ImeFunction fn, void *userData);
void ClayWidgets_RequestFocus(ClayWidgets_Context *ctx, Clay_ElementId id);
void ClayWidgets_Semantic(ClayWidgets_Context *ctx, ClayWidgets_SemanticNode node);
```

The semantic callback receives a `ClayWidgets_SemanticNode` during layout for
editors, buttons, checks and toggles, radio choices, sliders, menus, modals and
virtual lists. A node carries `id`, `parentId`, `role` (`BUTTON`, `CHECKBOX`,
`TEXT_FIELD`, `LIST`, `SLIDER`, `DIALOG`, `MENU_ITEM`, `ROW`, `GENERIC`),
`label`, `value`, `bounds`, and the `focused` / `disabled` / `selected` /
`readOnly` flags. Call `ClayWidgets_Semantic` yourself to describe custom
controls or composite rows, and merge nodes by id in the adapter. Strings are
borrowed for the duration of the callback and bounds come from the previous
frame; start and end the adapter's own collection around BeginFrame/EndFrame and
drop ids it stops seeing.

For IME, send transient preedit through `compositionUtf8`,
`compositionLength` and `compositionCursor`, and committed text through
`textUtf8` with the preedit cleared. Editors underline preedit without touching
the document. Install `ClayWidgets_SetImeFunction` to receive caret geometry and
place the platform candidate window.

`ClayWidgets_RequestFocus` lets an adapter request keyboard focus through the
normal modal and disabled rules.

These are adapter contracts, not native support: the platform layer owns native
composition events, clipboard failure reporting, and translating semantic nodes
into UI Automation, NSAccessibility or web accessibility trees. The raylib demo
does not acquire native composition events.

## Fonts (raylib backend)

```cpp
bool FontCache_Register(FontCache &cache, uint16_t id, const unsigned char *ttfBytes, int size,
                        const int *codepoints = nullptr, int count = 0);
void FontCache_Unload(FontCache &cache);
```

`FontCache_Register` registers a face under the same id used in Clay's text
configuration (the theme's `fontBody` / `fontHeading` / `fontMono`). The byte
storage must outlive the cache; glyph lists are copied. Registered faces are
searched in registration order for missing glyphs, and measurement and drawing
use the same per-glyph fallback. Default coverage is Latin-1 (ASCII 32-126 plus
160-255); supply glyph lists and fonts for any other scripts you need. The cache
bakes one atlas per pixel size on demand. Call `Clay_ResetMeasureTextCache`
after replacing a face in use, and `FontCache_Unload` before closing the
graphics context. This provides glyph fallback only - not shaping.

## Limits

- No grapheme segmentation, text shaping or bidirectional layout; word
  navigation treats non-ASCII codepoints as word characters.
- Font fallback is per-glyph, not shaping-aware.
- MSVC and strict C builds are unverified, as are Clay revisions other than the
  pinned one.
- Scroll panels are not designed to nest inside one another.
- Split and resizable panels are layout containers, not native windows or docks.
- Accessibility and IME are adapter APIs; no native screen-reader support ships
  here.

## Tests

`make test` and `make test-amalgam` run the frame-based regression suite (the
second against the generated single header). `python tools/build.py --test` is
the wrapper equivalent. `tests/test-raylib.cpp` covers font-id routing, fallback
measurement and drawing, and UTF-8 encoding in a hidden window; run it with
`make test-backend` on a machine with a graphics context.

CI runs the headless suites on every push, adds address and undefined-behavior
sanitizers on Linux, builds the desktop demo on Windows, and builds the
Emscripten demo published at <https://alessandroau.github.io/clay-widgets/>.
The demo's Gallery exercises the heavier controls: a 10,000-row data table, a
history-enabled editor, a searchable combo, a split pane and a resizable panel.
